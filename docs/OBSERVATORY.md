# Archimedes Observatory

Archimedes Observatory is the experiment layer above the Archimedes Engine. It is designed to make simulations challengeable rather than merely impressive.

## Core protocol

1. Freeze a seed, horizon, model parameters and shock.
2. Create deterministic counterfactual twins A and B.
3. Apply the same shock to both.
4. Apply a delayed policy/intervention only to B.
5. Compare terminal and time-series metrics.
6. Perturb each registered parameter locally and repeat the paired experiment.
7. Preserve the experiment specification, checksums, result and epistemic ledger as JSON.

## EFMW layer

The current engine implements an explicit EFMW adaptation: a lagged self-model **m**, coherence **C**, divergence **D**, recursive/gated state **phi**, local alignment surrogate **R**, and accumulated coherence **I**. These are experimental constructs in this repository. They are not represented as established physical observables.

The Observatory deliberately separates:
- **reference mechanics** — deterministic numerical field diffusion, motion, energy bookkeeping, interventions and seeded RNG;
- **EFMW hypothesis layer** — recursive self-model/coherence/divergence terms;
- **experiment evidence** — outputs generated by this simulator;
- **empirical evidence** — not supplied by a simulation and requiring external measurement.

## Sensitivity

The MVP uses local finite differences around the default parameter vector. Each parameter is perturbed while the seed, shock, policy and timing remain fixed. The displayed magnitude is the derivative-like change in the paired terminal composite outcome. This is a local, scenario-specific sensitivity diagnostic, not a global causal importance claim.

## Feedback after a shock

Feedback is explicit and time-indexed. Both twins receive the shock at 20% of the experiment horizon. Twin B receives the selected response after the configured delay. This makes policy feedback part of the model state transition rather than an after-the-fact narrative.

## Reproducibility

Every run exports:
- engine version;
- timestamp;
- complete experiment specification;
- terminal metrics for both twins;
- paired outcome delta;
- sensitivity table;
- epistemic/provenance ledger;
- checksums for both final worlds.

The regression harness in `tests/observatory.test.js` verifies deterministic replay, twin identity before intervention, finite sensitivity outputs, and the exported-record schema. It runs with the repository's standard `npm test` command.
